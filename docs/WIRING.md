### 由規格推出的常數

```
COUNTS_PER_WHEEL_REV = 13 PPR × 4 (四倍頻) × 10 (減速比) = 520
L_SUM = LX + LY = 0.102 + 0.1625 = 0.2645 m
```

> **520 這個數字是有旁證的**：Tomcat 那台車用捲尺在地板上實測校正出 **530 ± 1.5%**，
> 與這裡由規格算出的 520 差不到 2%。兩台車很可能是同型馬達。
>
> ⚠️ **但仍然必須用捲尺實測確認**。這個常數同時縮放 PID 的**量測值與 setpoint**，
> 所以它錯的時候迴圈依然「完美跟隨目標」，里程計也會用同一個倍率少報——
> **任何自洽性檢查都抓不到它**。只有地板上的捲尺看得見。
> Tomcat 就是這樣被騙了很久（原本猜 1320，實際 530，差 2.5 倍）。

## 2. 動手前：三條會燒東西的規則

1. **接線時 12V 電源必須斷開。** VM 帶電時插拔馬達線可能造成反電動勢突波。
2. **驅動板 GND 必須拉一條線直接到 ESP32 的 GND。**
   你的供電架構是「電池 → 主機 + 驅動板」，而 ESP32 吃主機的 USB 電。
   理論上共地是透過「電池負極 → 主機電源 → 主機 USB 地 → ESP32 地」這條又長又繞的路徑，
   而且**如果主機用的是隔離式 DC-DC，這條路根本不通**。
   直接拉一條 GND 是必要的，不是保險。沒共地的症狀是「馬達隨機亂轉或完全不動」，
   而且看起來完全像軟體問題。
3. **量到 encoder 訊號是 5V 就不可以直接接 ESP32。** 見第 5 節。

## 3. 電源架構（依你的實際配置）

```
   電池 ──┬──► 主機 ──USB──► ESP32（供電 + serial）
          │                      │
          └──► 驅動板 VM (12V)   │
                   GND ──────────┘  ← 必拉的直接共地線（第 2 節）

   ESP32 3V3 ──┬─► 驅動板 VCC （邏輯電源，3.3V）
               └─► 驅動板 STBY（跳線直接拉高，見 5.3）
```

✅ **你的配置沒有雙重供電問題**：ESP32 只吃 USB，驅動板的 5V 輸出不接 ESP32。維持這樣。
⚠️ 之後若要把 ESP32 改吃驅動板的 5V，**必須先拔掉 USB**，否則兩個電源互灌。

**驅動板的 VCC 建議接 3.3V，不要接 5V。**
TB6612 邏輯電源規格 2.7–5.5V。接 3.3V 時它的輸入高準位門檻對 ESP32 的 3.3V 輸出餘裕充足；
接 5V 則門檻升高，3.3V 訊號落在邊緣地帶（能動，但雜訊餘裕變小）。

## 4. GPIO 預算：為什麼腳位不能亂配

| 類別 | 腳位 | 說明 |
| --- | --- | --- |
| 🚫 絕對不能用 | 6, 7, 8, 9, 10, 11 | 接內部 SPI flash，一接就開不了機 |
| 🚫 絕對不能用 | 1 (TX0), 3 (RX0) | UART0，micro-ROS 走這條 |
| 🚫 **本專案禁用** | **12 (MTDI)** | 開機被拉高 → flash 供電變 1.8V → **bootloop**。Tomcat 車就是死在這裡，`erase_flash` 全抹重燒都救不回來。**這台車刻意完全不接它** |
| ⚠️ 不用 | 0 | BOOT 鍵共用 |
| ⚠️ 有條件可用 | 2, 5, 15 | strapping pin，開機瞬間有訊號輸出（見 3.3 節的 STBY 設計） |
| ⚠️ 只能當輸入 | 34, 35, 36, 39 | input-only，**無內部上下拉** |
| ✅ 乾淨可用 | 4, 13, 14, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33 | 15 支 |

✅ **GPIO16 / 17 確認可用**：這片是 WROOM-32，模組內沒有 PSRAM
（`firmware/tiny_probe` 實測 `PSRAM ID read error` + `psramFound() = false`）。
若當初是 WROVER，這兩支會被 PSRAM 佔走。

需求：`12（馬達）+ 1（STBY）+ 8（encoder）+ 1（LED）= 22 支`
可用：`15 乾淨 + 3 有條件（2/5/15）+ 4 input-only = 22 支`

**剛好用完，一支不剩。** 之後若要加 IMU（I2C 2 支）或光達（UART 2 支），
最省的方法是把驅動板的 `PWMA`/`PWMB` 跳線拉到 VCC、改用 IN1/IN2 打 PWM，一次省 4 支。
（代價：decay mode 從 slow 變 fast，低速線性度變差，FF 與死區要重調。）

## 5. ✅ ESP32 腳位表（定案）

輪子編號全專案固定：**FL=0（前左）, FR=1（前右）, RL=2（後左）, RR=3（後右）**。

### 5.1 馬達控制 → 驅動板

| 輪 | IN1 | IN2 | PWM |
| --- | --- | --- | --- |
| **FL** 前左 | GPIO **13** | GPIO **14** | GPIO **27** |
| **FR** 前右 | GPIO **16** | GPIO **17** | GPIO **15** |
| **RL** 後左 | GPIO **18** | GPIO **19** | GPIO **5** |
| **RR** 後右 | GPIO **22** | GPIO **23** | GPIO **21** |

| 訊號 | 腳位 | 備註 |
| --- | --- | --- |
| **STBY** | — | **本車已用跳線直接接 3V3**（D64A 只有一根 STBY）。GPIO4 因此空出來變成備用腳 |
| **LED** | GPIO **2** | 板載 LED，狀態指示。不接外部東西 |

> ✅ 好消息：GPIO4 空出來了，這是全機**唯一的備用腳位**（GPIO12 永久禁用不算）。

### 5.2 Encoder

八條訊號線集中在開發板同一側（36/39/34/35/32/33/25/26），可以走同一束排線。

| 輪 | A 相 | B 相 |
| --- | --- | --- |
| **FL** 前左 | GPIO **34** ⚠️ | GPIO **35** ⚠️ |
| **FR** 前右 | GPIO **36** (VP) ⚠️ | GPIO **39** (VN) ⚠️ |
| **RL** 後左 | GPIO **32** | GPIO **33** |
| **RR** 後右 | GPIO **25** | GPIO **26** |

⚠️ 標記的四支是 input-only、**沒有內部上拉電阻**。
**建議八條 encoder 線全部外加 10kΩ 上拉到 3.3V**：

- encoder 輸出若是 open-drain／open-collector，**沒有上拉就完全讀不到**
  （症狀：那兩輪 tick 永遠 0，看起來像 encoder 壞了）。
- 若是推挽輸出（多數霍爾 encoder 是），多一顆 10kΩ 只多耗 0.33 mA，**完全無害**。

加上去比事後除錯便宜太多。

### 5.3 ⚠️ STBY 跳 3V3 的代價：開機約 300 ms 內 FR / RL 可能抽動

**現況**：D64A 只有一根 STBY，已用跳線直接接 3V3，所以**驅動器從上電那一刻就是致能的**。

為什麼這會有影響：ESP32 重置時各腳預設狀態不同。
**GPIO5 和 GPIO15 內部是上拉（開機為高）**，而且它們是 strapping pin，
**開機瞬間會輸出一小段訊號**——它們正是 **RL 和 FR 的 PWM 腳**。
同一時間 IN1/IN2 還是浮接的輸入（要等韌體 `setup()` 跑到才被驅動為低）。

```
上電 → STBY 已經是高（跳線）→ TB6612 輸出live
     → GPIO5/15 輸出 boot 訊號、IN1/IN2 還浮接
     → FR 與 RL 可能抽動  ← 約 300 ms 的視窗
     → 韌體 setup() 第一行就把馬達腳位驅動為低 → 結束
```

**影響評估**：車架高時完全無所謂；落地時是一個小竄動。不會壞東西。
韌體已經把馬達腳位初始化**移到 `setup()` 的第一個動作**，把視窗壓到軟體能做到的最短。
`tiny_open.ino` 的註解裡註明了那段不可以被其他初始化插隊。

**如果之後想把保護裝回來**：把 STBY 改接 GPIO4，加一顆 10kΩ 下拉到 GND，
然後把 `config.h` 的 `STBY_ON_GPIO` 改成 `1`。GPIO4 在重置時是浮接的（無內部上下拉），
下拉電阻就能保證整個開機過程驅動器都是關的。這顆電阻是整條線路裡最划算的零件——
但既然線已經接好，先跑起來再說，不急著改。

## 6. ⏳ 驅動板側（D64A）——待確認

`D64A` 這個型號我在網路上查不到公開的接口定義，所以下面是**待你確認的假設**。
從你的描述（雙 TB6612 集成、12V 輸入、同時驅四顆），它屬於市面常見的
「TB6612 四路編碼馬達驅動板」這一類——這類板子通常長這樣：

- 四個 **XH2.54 馬達接頭**（標 A / B / C / D 或 M1~M4），每個接頭**同時包含**
  馬達的 M+/M− **和** encoder 的 VCC/GND/A/B（所以馬達的 6 芯線是整條插進板子的）
- 板上有 **5V 穩壓輸出**
- 另有一排給 MCU 的控制排針（PWM/IN1/IN2/STBY）與 encoder 訊號輸出排針（EA/EB…）

### 🔴 最重要的一件事：量 encoder 的供電電壓

**如果馬達的 encoder 線是插在驅動板上的，那 encoder 吃的是「板子給的電」，
不是馬達規格書上寫的電壓。** 板子若餵 5V，encoder 的 A/B 就會輸出 5V ——
**ESP32 的 GPIO 不是 5V 容忍，接上去會慢慢燒掉輸入腳**（通常不會馬上死，
而是變得時好時壞，最難除錯的那種故障）。

**確認方法（先做這個，再接任何線）：**

```
1. 只給驅動板 12V。馬達不接、ESP32 不接。
2. 用三用電表量「馬達接頭上 encoder VCC 那一腳」對 GND 的電壓。
3. 讀到 3.3V → 可以直接接 ESP32。
   讀到 5V   → 不可直接接。找板上有沒有 3.3V/5V 跳線；
              沒有的話每條 A/B 線要加分壓（10kΩ + 20kΩ）或電平轉換板。
```

### 待確認清單

- [x] STBY 只有**一根**，已用跳線直接接 3V3 → GPIO4 空出來（代價見 5.3）
- [ ] 🔴 **板子餵給 encoder 的 VCC 實測電壓**（3.3V 還是 5V）——**通 12V 前必做**
- [ ] 驅動板的邏輯 `VCC` 接的是 3V3 嗎？（接 5V 也能動，但雜訊餘裕較差）
- [ ] `PWMA`/`PWMB` 有沒有跳線可以直接拉高？（純粹是日後想省腳位時的退路，現在不需要）

## 7. TB6612 真值表（除錯時對照）

| STBY | IN1 | IN2 | PWM | 輸出 |
| --- | --- | --- | --- | --- |
| L | × | × | × | **Standby（全關）** |
| H | H | L | PWM | 正轉（PWM 低電位時 short brake → slow decay） |
| H | L | H | PWM | 反轉 |
| H | H | H | H | Short brake（急停） |
| H | L | L | × | Stop（自由滑行 / coast） |

本專案韌體用 **IN1/IN2 定方向、PWM 腳打工作週期**的 slow-decay 模式。

- 馬達的兩條粗線接反 → 只是轉向相反，用軟體 `MOTOR_DIR` 修，**不必重焊**。
- encoder 的 A/B 接反 → 只是計數方向相反，用軟體 `ENC_DIR` 修，**不必重焊**。

## 8. 通電前的檢查（照做，不要跳）

1. **12V 還沒接**，先只接 ESP32 的 USB。量 3V3 對 GND 應為 3.3V 左右。
2. 用三用電表**通斷檔**確認：ESP32 GND、驅動板 GND、電池負極三者導通。
3. 確認 **GPIO12 沒有接任何東西**（本專案最重要的一條）。
4. 確認 STBY 的 10kΩ 下拉裝好；量 GPIO4 對 GND 應約 10kΩ。
5. **完成第 6 節的 encoder 電壓量測**。
6. **輪子離地**（車架高）。
7. 接 12V，量驅動板 VM 應為 12V、VCC 應為 3.3V。
8. 這時才燒 `firmware/tiny_open`，跑第一次方向校正（見 `docs/BRINGUP.md`）。
